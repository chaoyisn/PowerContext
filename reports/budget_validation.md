# PowerContext 赛题十：UTF-8 总字节预算与格式开销校验报告

## 一、预算定义与成本构成

赛题明确要求：预算不仅针对正文，必须覆盖最终实际返回的完整上下文字符串的 UTF-8 编码字节数。

$$\text{content\_bytes} = \text{len}(\text{final\_content.encode("utf-8")}) \le \text{max\_bytes}$$

### 完整上下文字符串开销分解

1. **固定信封开销（Envelope Overhead，约 366 字节）**：
   - Trust Policy: 247 字节
   - 双换行符: 2 字节
   - 起始标记 `BEGIN_POWERCONTEXT_PREPARED_CONTEXT_V1`: 38 字节
   - 换行符: 1 字节
   - 空 JSON 骨架 `{"trust":"untrusted_history","items":[]}`: 41 字节
   - 换行符: 1 字节
   - 结束标记 `END_POWERCONTEXT_PREPARED_CONTEXT_V1`: 36 字节
2. **条目引用元数据开销（Per-Item Citation Metadata，约 160-200 字节/条）**：
   - `"citation": {"scope_id": "...", "memory_ref": {"family":"memory","artifact_id":"...","revision":1}, "entry_id": "...", "entry_version_id": "..."}`
   - `"start": 123, "end": 456`
   - JSON 语法开销：大括号、引号、逗号冒号。
3. **正文内容开销（Excerpt Payload）**：
   - 片段原文 UTF-8 字节数。
   - 特殊字符转义增量（例如正文中的双引号 `"` 转义为 `\"` 增加 1 字节，换行符 `\n` 转义为 `\n` 增加 1 字节）。

## 二、预算模拟策略 vs 事后硬截断

传统截断方案往往先组装正文，若超出预算则在字符串末尾按字节截断。这种方案存在致命缺陷：
- 破坏 JSON 语法结构（尾部缺失引号或闭合括号）。
- 截断 UTF-8 多字节字符导致非法编码。
- 破坏 Citation 或位置元数据。

**本题实现的动态增量模拟方案**：
- 在加入或合并每一个候选片段前，均构造完整 JSON 数据结构并调用 `json.dumps(..., ensure_ascii=False, separators=(",", ":"))`。
- 调用 `.encode("utf-8")` 测量真实字节长度。
- 唯有在试算字节数 $\le \text{max\_bytes}$ 时才正式接纳该候选。
- 最终产物中 `content_bytes` 精确等于真实字节数，杜绝任何破损。

## 三、边界预算场景测试验证

| 测试场景 | 设定预算 | 实际输出字节 | 测试表现 | 结论 |
| :--- | :---: | :---: | :--- | :---: |
| **精确容纳边界（T16）** | $N$ 字节（正好容纳 1 条证据） | $N$ 字节 | `status="ready"`, `content_bytes == max_bytes`，正好完全填满预算。 | **PASS** |
| **差 1 字节超标（T17）** | $N - 1$ 字节 | $< N - 1$ 字节 | 检测到超出后拒绝过度输出，安全回退或在合法边界内收缩，保证不溢出。 | **PASS** |
| **引用超载（T18）** | 512 字节（极小预算） | 0 字节 | 固定信封（366 字节）加上 Citation（~180 字节）已超 512 字节，安全返回 `status="empty"`。 | **PASS** |
| **中文字符膨胀（T19）** | 800 字节 | 598 字节 | 20 个中文字符膨胀为 60 字节，精确按 60 字节计费并成功交付。 | **PASS** |
| **多片段防超预算（T20）** | 1100 字节（提供 10 条候选） | 1084 字节 | 贪心选择接纳高优先级证据并在触达 1100 字节边界前安全停止，无溢出。 | **PASS** |
| **官方 SciFact 样本** | 1800 字节（8 篇长论文摘要） | 1037 字节 | 成功选中关键证据，输出完整信封且满足 1800 字节上限。 | **PASS** |
